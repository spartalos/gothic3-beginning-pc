# Classes B, C, D (names: GameWorld, LoadTask, SoundThread)

Sources: the decompiled `B.java`, `C.java`, `D.java` (generated by `setupGame`, `game/gen/src/g3/`), cross-checked against A/HG and the packed data files `d` (map data, 97550 bytes) and `a` (image table).
Mapping files: `docs/mapping/{B,C,D}.map` (all 184/10/6 members mapped). "A.xx" below means obfuscated members of class A (named by another agent).

Correction to early findings: `B.k` is NOT an animation frame. It is the palette theme (0..4) of the current map. There is no tile animation in the tile layers.

## 1. World representation

### 1.1 Units
* Tile size: `B.d` x `B.e` px = 16x16 (8x8 on map 0 = overview map; `A.ea[11]==0`). For the random map the size is `ec[ts*11+0]/ec[ts*11+5]` (image width / columns).
* ALL entity positions are 12-bit fixed point in tile units: 4096 = 1 tile, `tile = pos >> 12`, `px = pos * B.d >> 12`. Hitboxes/speeds are in the same unit. Per-type pixel offsets in the data files are converted with `(byte << 12) / B.d`.
* Tile coordinates are packed in one int as `x | (y << 16)` (two shorts, read with `(short)(v & 0xFFFF)` and `(short)(v >> 16)`). This "packed point" is used everywhere (entity[0], path nodes, script params...).

### 1.2 Tile grid `B.g[y][x]` (int, two 16-bit layers)
Layer L (0 = ground, 1 = overlay) occupies bits `16*L .. 16*L+15`.
Layer 0 (bits 0..15):
| bits | meaning |
|---|---|
| 0-7 | tile index in tileset image, `% cols` -> x, `/ cols % rows` -> y (cols/rows = `ec[ts*11+5/6]`); 0xFF = empty (cell value 0xFFFF = void) |
| 8-10 | `Graphics.drawRegion` transform (0..7: none, mirror-rot variants) |
| 11 | unused |
| 12-14 | runtime: head of overlay sort chain for this row (see 1.4); 7 = none. Cleared and recomputed by `A.L()` after load |
| 15 | WALKABLE flag (set by the map editor). Walkable iff `bit15 set && (tile & 0xFF) != 255` (`A.C(x,y)`); this is the only terrain collision data |

Layer 1 (bits 16..31): bits 16-23 tile index (0xFF empty), 24-26 transform, 28-30 = overlay depth tag (file value, 0..6; 7 = empty), 31 = scratch (cleared by `A.L()`).
Tileset of each layer: `B.f` low16 = layer 0 tileset id, high16 = layer 1 tileset id (rows of table `A.ec`, section 1.5). Set from the map file; the random map uses `f = 0x00030000` (layer0 ts 0, layer1 ts 3) or `0x00070007` (dungeon kind).
Gameplay collision is therefore: tile walkable bit + the dynamic half-tile occupancy grid `A.ya` (2x2 cells per tile, 3 ints per cell; used for pathfinding/occupancy, `B.setPathParent/getPathParent` store BFS parent coordinates in 2x7 bits of `ya[..+2]`) + entity hitboxes (1.3).

### 1.3 Hitboxes and collision (`B.getHitbox`)
Entity position is the feet/anchor point. Box = pos + (minX,minY) .. pos + (maxX,maxY):
* player (flag 16): x -1024..+1024, y -2048..+256 (i.e. 0.5 tile wide, 0.5625 tall).
* creature (flag 32): `A.ha[type][2]` (minX low16 | minY high16) and `[3]` (maxX | maxY).
* static object (flag 4096): `A.sa[type][2],[3]` (same packing).
Rect overlap = `hitboxesOverlap`. Movement `moveEntity(ent, x, y, mask)` moves per axis (`moveAlongAxis`), checks every tile touched by the new box with `A.C`, then entity overlap through the spatial hash; if blocked on a diagonal move it tries to slide along the wall (`probeWallSides`). Return: -2 free, -1 blocked by terrain, >=0 index (in B.a) of the blocking entity. Entities with flag 32768 are ignored. Masks: 4128 = creatures|objects (0x1020), 4144 = + player (0x1030). `castRay` walks tile borders then tests entity boxes (-2 clear, -1 terrain, else entity index); used for line of sight (`hasLineOfSight`) and projectiles.

### 1.4 Spatial hash and draw order
* `B.cellHeads[y][x]` = first entity index in that tile (-1 = none). Chain: low16 of `entity[1]` = next entity in same tile. `insertIntoGrid`/`removeFromGrid` keep it in sync; flag 2 = "currently in grid". Only entities with a tile position in range are inserted.
* `queryRectChain(rect, flagMask)` collects overlapping entities into a temporary list linked via **high16 of entity[1]**; returns head (-1 empty). Loop pattern: `for (i = head; i != -1; i = (short)(a[i][1] >> 16))`.
* Draw (A.D(Graphics)): for each visible tile cell all entities are insertion-sorted (by `getSortY`, the bottom of the hitbox; objects use pos.y + `sa[type][4]`) into one list using high16 of `entity[1]`. Then: layer 0 from an offscreen buffer; items/flat objects; player + creatures; then rows are walked top to bottom: before processing row r all sorted entities with `sortY <= (r+1)*4096` are drawn, then the layer-1 tiles that belong to row r. A layer-1 tile at row y with depth tag t is drawn when row y+t is processed (so tall trees/walls hide sprites standing behind them). `A.L()` precomputes the chains: cell(y+t).bits12-14 = first t, `cell(y).bits28-30` = next t of the same sort row, 7 = end.

### 1.5 Image/tileset table `A.ec` (short[273*11], file `a`)
File `a`: `short n; short[n] ec; short k; (short m; short[m])[k] -> HG.eA; short j; short[j] -> A.sA`. `ec` row = image id, 11 shorts:
| col | meaning |
|---|---|
| 0,1 | image width, height (px) - filled at load time |
| 2 | frame count (from `NNN.off` sprite-offset file, or cols*rows) |
| 3 | resource number in packed image resource `/i` (-1 = none; ids 300+ etc.) |
| 4 | recolour-table index into `A.cC` (-1 none). Value 5 is special: variant = `B.k` (theme) |
| 5,6 | columns, rows of the frame grid (tilesets: tile = width/cols x height/rows) |
| 7,8 | anchor mode x,y for generated frames: 0 top-left, 1 = minus full frame size, 2 = centred |
| 9 | bit flags: 1 = load failed, 2 = keep resident, 4 = present in packed pack `/i` |
| 10 | fallback image id (used if load fails) |
Frame table `A.fc[img]`: 7 shorts/frame `{img, srcX, srcY, w, h, offX, offY}`.
Tileset rows seen: 0 (6x7 tiles), 1 (3x6), 2 (4x9), 3 (11x5), 4 (4x8, recoloured), 5 (4x9), 6 (4x6, recoloured), 7 (4x5). Fixed maps use ts 0,1,4,5,7 for layer 0.

### 1.6 Data file `d` (map data) - verified by script
```
repeat in order: [short size][short count][records...]   (size counts the count field => next table at +2+size)
  1 monster types  -> A.ha  (97 rows x30 ints)     5 armor types  -> A.la (14 x14)
  2 stackable types-> A.na  (17 x7)                6 object types -> A.sa (81 x6)
  3 misc item types-> A.qa  (18 x5)                7 item types   -> A.va (13 x12)
  4 weapon types   -> A.ja  (35 x17)               8 item types   -> A.xa (7 x11)
                                                   9 affix types  -> A.ta (14 x5)
(if the A.* table already exists the block is skipped)
then: short unknown(=25764); short mapCount(=144); mapCount x [short size][size bytes]
```
Map entry i: 0..52 = the real game maps, 53..143 = 91 "prefab" sub-maps (rooms/areas stamped into random levels; counts per class in `B.prefabCounts`).
```
short width, short height, byte layerCount(=2)
per layer: short w, short h, byte tilesetId, byte compression
   0 = raw: w*h x [byte tile][byte flags]
   1 = RLE: byte n; n<0 -> |n| empty cells (0xFFFF); n>=0 -> n literal cells of 2 bytes. Cells row-major.
   (cell value = (tile | flags<<8) << (16*layer))
then the entity sections in this order: creatures, stackables, miscItemsQa, weapons(ia), armor(ka), objects(ra), jewelry/Va(ua), itemsXa(wa), triggers(fC), scripts(eC)
```
Entity section records (all start with a byte count):
* creature (-> A.ga[32]): byte typeIdx, byte x, byte y, byte weaponSlot0, byte weaponSlot1 (-1 none, -2 = no random), byte dropFlags(1/2/4), 2x{byte kind (2,3,5 + byte value, else none)}, byte aux. Initial pos = `(x*4096+2048, y*4096+4095)` (bottom-centre of tile). HP low16/high16 = `ha[type][6]`.
* object (-> A.ra[11]): byte type, byte x, byte y, byte offX, byte offY (pixel offsets, /tileW), byte z, byte, byte kind, byte param. pos = tile*4096 + 2048 + (off<<12)/tileW (x), and bottom for y. `kind` (ra[8] low byte): 0 decor, 4 = loot spawner/chest (random contents), 5 = openable/stateful (bit index in per-map state mask in bits 8-15), 8 = random spawner. State bits persist per map in `A.bA[mapId]` (`getObjectStateBits`).
* item instances ia/ka/ua: byte type, byte x, byte y (subtile bytes) , byte flag(1 = affixes rolled); ma/oa/wa similar. Dynamic items (drops) are appended in the slack capacity (+15) with `[4] < 0` = free slot (`A.A(int[][])` finds the free slot).
* triggers `A.fC[n][7]`: [0] type, [1] enabled, [2..5] params, [6] script index. Types 8 = entered rect, 13 = left rect, 18 = standing in rect (params x0,x1,y0,y1), others point/interaction triggers. Scripts `A.eC[n]` are opcode byte streams executed by `A.O(int[],int)`; opcode 41 = map transition, 45 = load map (`LoadTask`), 46 = set facing.
Map ids with special palette theme (`B.k`): 5,16,3,24 -> 0; 4,15 -> 1; 6,17 -> 2; 7,18 -> 3; 12,48 -> 4; others keep the previous/0.

### 1.7 Map loading / transitions
`LoadTask.run` (thread): `A.A(3)` (loading state) -> `B.loadMap(id,x,y)` or `B.generateRandomMap(kind,layout,side)` (falls back to `loadMap(0, savedPos)` on failure) -> start music (`HG`) -> `A.A(6)` (playing). Progress `LoadTask.progress` (C.c) goes 0..100 and is drawn as the loading bar.
`loadMap`: (only if player HP>0) `unloadMap` of the old map; if `ea[11] != id` fade (`A.FA(3)` = autosave), `A.ea[11] = id`; open resource `d`; `readTypeTables` (skipped when present); `readMapEntry` (finds entry id, `readMapGrid` + `readMapEntities`); `A.ZA()`; `initMapRuntime(x,y)` (allocates `B.cellHeads`, `A.ya` half-tile grid, builds `A.L()` chains, `buildEntityTable` which flattens ea+ga+ra+ia+ka+ma+oa+ua+wa+kA+lA+sD into `B.a` and sets per-class flags and indices (entity[2] low16 = B.a index, high16 = index within its own list), inserts into the grid, `markMapResources`, camera init `A.IA()`, music id from the layer-1 tileset). `A.ea[11]` = current map id (-1 = random map, then `B.randomMapStateBits` is used for object state bits).

### 1.8 Random levels (B.generateRandomMap, 32x32)
Used for the procedural dungeon/forest levels (`A.ea[11] == -1`, `B.generatorKind` 0/1/2). Steps: `initGenerator` (terrain grid `B.terrainGrid`, 14 terrain types in `B.terrainTiles`, 6 bytes each: 4 tile variants, autotile set, corner-variant flag; interior variant = type+1 when all 8 neighbours equal) -> `generateTerrain` (kind 2: BSP rooms `generateRooms` + corridors, otherwise noise `scatterTerrain`/`growTerrain` + `carvePath`/`carveRoad`) -> `bakeTiles` (autotile through `B.autotileLookup`, 4-neighbour mask -> {transform,variant}) -> `decorateWalls` (kind 2) -> `fillBorder` -> `placeSpecialArea` + `placePrefabs` (stamps prefab sub-maps) -> `placeEntrance(side)` -> `populateSpawners`/`spawnCreatures` (monster groups chosen by player level `A.ea[18]` from `A.ha`) -> `buildReturnEvents` (four border trigger rects, script 41 back to the previous map position) -> arrays resized and `initMapRuntime`. Randomness via `HG.A(n)` (random int [0,n)) and `HG.A(a,b)`.

## 2. Entity model (`B.a[i]` rows of int)
Common header (all classes):
| idx | meaning |
|---|---|
| 0 | tile position packed (x | y<<16); -1 when carried/absent |
| 1 | low16 = next in same-tile chain (-1 = end); high16 = temp sort/query chain |
| 2 | low16 = index in B.a; high16 = index in the class's own list |
| 3 | flag word (below) |
| 4,5 | **mobile entities (flag 8)**: fixed-point x,y. **Items/objects**: [4] = type index (-1 = free slot) |
| 11 | creature: type index into A.ha. (player: current map id) |
Flags (`entity[3]`): 2 in spatial grid; 4/8 mobile actor / has fixed-point pos [4],[5]; 16 player; 32 creature (type table A.ha); 64 weapon item (A.ia -> A.ja); 128 armor (A.ka -> A.la); 256 stackable (A.ma -> A.na, qty in [6]); 512 misc item (A.oa -> A.qa); 1024 A.wa -> A.xa; 2048 A.kA (projectile-like: rect in [4..7], pos = centre); 4096 static object (A.ra -> A.sa; pos = tile<<12 + sub-tile in [5]); 8192 A.ua -> A.va; 16384 A.sD; 32768 ignored by collision; 65536 hidden / in an inventory (not drawn, not in grid); 131072 magic item (affixes in [6],[7] = amount | A.ta index<<16); 262144 A.lA; 2097152 temporary mark. `A.A(int[])` resolves flag -> type-table row.
Player `A.ea` (>=54 ints): [4],[5] pos, [11] map id, [12] HP (cur low16 | max high16), [16] max step = 1024, [17] xp, [18] level, [30] facing, [52] current step, [45] script/dialog state. Init in `A.AA()`: pos (2048,2048).
Creature `A.ga[32]`: [4],[5] pos, [11] type, [12] HP cur|max, [13] behaviour flags (64 = following a path, ...), [14],[15] held weapon instances, [17],[18] loot refs (kind | index<<16), [19] gold, [20] target, [22],[24] path target/step, [28] alert timer, [29] speed (step per tick, 1/4096 tile), [30] facing.
Facing (`[30]`): 0 = up (y-), 1 = right, 2 = down, 3 = left.
Type table `A.ha` columns (by file read order; names are for A's mapper): [0] name id, [1] sprite/anim set, [2],[3] hitbox, [5] level, [6] max HP, [7] strength, [8] dexterity, [9] = 4096/anim byte, [13] flags (1<<n class bit | 128,512,1024,2048), [21],[22] loot kinds, [23],[24] default weapon classes, [25] drop chance %, [26] ammo class, [27] class (0-4 monsters, 5/6 other, 7/8 chests/containers), [29] speed = byte*4096/10.

### Movement per tick (needed for interpolation)
* One game logic step per rendered frame; frame period is fixed 100 ms (10 fps) in `A.run()`: `p++` frame counter, `sleep(100 - elapsed)`.
* Player: step `A.ea[52]` per tick; max `ea[16]=1024` (0.25 tile/tick = 2.5 tiles/s); starts at 512, `+= ea[16]>>3` (128) every tick while moving freely (`moveEntity` returned -2), resets to 512 when blocked or idle. Diagonals use `step = isqrt(step*step/2)`. Dirs from key flags eB up, fB down, cB left, dB right (A statics). Position update is `B.moveEntity(ea, x, y, 4128)`; then tile change fires triggers.
* Creatures: step `ga[i][29]` (`ha[type][29] = byte*4096/10`), path following through `A.ya`/`A.za`.
* For smooth 60+ fps: interpolate `pos(t) = prev + (cur-prev)*alpha` between 100 ms ticks, keep the 10 Hz logic.
* Stat regeneration etc. run on `A.p % 20 == 0` (every 2 s).

## 3. Camera / scroll (A.vB, A.wB; `A.IA()`, `A.JA()`)
`vB,wB` = top-left of the screen in px (screen `A.f` x `A.g`). Initial: player px - half screen. Each tick target = player px - half screen, shifted 1 tile in the facing direction (look-ahead); if a target creature `A.iB` is within ~screen the target is the midpoint of player and creature. Smoothing: `cam = (cam*100 + target*28) >> 7` (22% toward target per tick). Clamped to `x in [0, mapW*tw - screenW]`, `y in [-3*th, (mapH+3)*th - screenH]` (map 0: y from `-ae`, to `(H+5)*th - screenH`); if the map is smaller than the screen it is centred. Layer 0 is cached in an offscreen image `A.vA` (screen+2 tiles) re-blitted with tile-aligned incremental updates (`A.M()`).

## 4. Timing summary
* Main loop (A.run): logic+paint, min 100 ms per frame. `A.p` frame counter wraps at 100000.
* `SoundThread`: polls every 100 ms; `LoadTask` runs on its own thread; `System.gc()` is called heavily around loads.
* Counters: `A.p % 20` regen (2 s); path/AI timers decrement per tick (`ga[..][28]`, `nB`, `oB` footstep sound every 4 steps).

## 5. LoadTask (C) and SoundThread (D)
C: `setupMapLoad(game,mapIdOrKind,x,y,random)` / `setupInitLoad(game,stage)`; `run`: stage>0 -> `A.IA(stage)` (initial resources: fonts, strings, `MA()` images, `RA()`, `HG.L()`, shows screen 159); else map load/generate as in 1.7, then restarts music if not playing. `progress=100` at the end. Started with `new Thread(A.s).start()` (A.s is the shared LoadTask).
D: static queue of sound ids. `enqueue(id)` is called by `HG.M(id)` for sounds whose flag bit 2 is set; every 100 ms the thread pops all queued ids and calls `HG.Q(id)` then `HG.R(id)` (start/priority + lookup) unless `HG.ha` (paused) is true, in which case it calls `HG.O()` (pause all). `stopSound(id)` -> `HG.L(id)` (stop+deallocate player).

## Hints for other classes
* `A.C(int,int)` = isWalkable(tileX,tileY) (layer0 bit15 && tile != 255). `A.L()` = precompute overlay sort chains. `A.J()` allocates the layer-0 offscreen buffer; `A.M()`/`A.F(Graphics)` draw it; `A.D(Graphics)` = world render (entities+layer1). `A.A(int,int,int,Graphics)` draws one tile of layer 0/1.
* `A.ya` = half-tile (2x2 per tile) pathfinding/occupancy grid, 3 ints per cell: [0],[1] node data, [2] bits 0-13 BFS parent (2x7 bits), bits 14-15 blocked state (32768 solid, 16384 occupied), bits 16-23 owner creature, 24-31 path step. `A.za[creature]` = remembered path.
* `A.ec` = image table (see 1.5); `A.L(int,int)` = load image variant; `A.W(int)` = load image variant 0; `A.K(img,variant)` / `A.A(boolean,int,int)` = mark/load needed images; `A.MA()` allocates fc/gc/hc and reads pack `/i`; `A.G()` reads file `a`.
* `A.ha/ja/la/na/qa/sa/va/xa/ta` = type tables (see 1.6); `A.ga/ia/ka/ma/oa/ra/ua/wa/fC/eC` = instances; `A.ea` = player; `A.bA/cA/dA/eA/fA/gA/hA/iA[mapId]` = per-map persistent bitmasks (bA: objects state, cA: ma removed, dA: oa removed, eA: creatures dead, fA/gA/hA/iA: ia/ka/ua/wa removed); `A.jA` = inventory list heads (4 or 5 per container: 2 low16 = head, high16 = count).
* `A.p` = frame counter, `A.s` = LoadTask instance, `A.f/g` = screen size, `A.vB/wB` camera, `A.iB` = current target creature, `A.eB/fB/cB/dB` = held direction keys (up/down/left/right), `A.gB` action key. `A.bb` = layer-0 buffer dirty flag; `A.ae` = HUD height offset for camera clamp on map 0.
* `A.A(int[],boolean)` toggles occupancy on `A.ya`; `A.V(int)` = random gold amount for a creature; `A.CA(int)` = random loot amount for a spawner.
* `HG.A(n)` = random [0,n), `HG.A(a,b)` = random [a,b]. `HG.M(id)` = play sound/music, `HG.L(id)` = stop, `HG.Q/R/O/P` = start/lookup/pause-all/resume-all, `HG.ha` = paused, `HG.ba` = the SoundThread instance, `HG.S(id)` = player state, `HG.I(n)` = localized string n.
* Event opcodes in scripts: 41 map-change message/transition, 45 load map (`LoadTask`), 46 set facing, 40 hide entity, 47 open/trigger object, 44 teleport entity.

## Open questions
* Exact meaning of several `A.ha` columns and of each item type table (ja/la/va/xa/qa semantic names are guessed from usage: weapons/armor/stackables/affixes are fairly certain, va/xa/qa are not).
* First short after the tables in file `d` (25764) is unused by the code.
* `B.needPathGrid` (B.i) is never set to false; presumably a leftover.
* Flag 4 / 262144 / 16384 semantics (A.lA, A.sD, A.kA lists) are for the A mapper; kA looks like projectiles, lA/sD like spell effects/floating text.
* Creature step unit: `ga[29]` is applied per AI tick in `A.R/…` but I did not trace the exact per-tick update site for creatures.
* Whether other (non-random) maps use tile layer animation: none found; water etc. are static.
