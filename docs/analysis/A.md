# Class A -> `GameEngine`  (extends GameCanvas implements Runnable)

Mapping: `docs/mapping/A.map` (231/257 fields, 327/348 methods; the rest are empty stubs, scratch vectors or unclear).
Names below use the proposed names; obfuscated names in `code` are given where it helps cross-referencing.
All line numbers refer to the decompiled `A.java` (generated by `setupGame`, `game/gen/src/g3/`).

## 0. One-paragraph model of the game

Top-down 2D tile RPG (Zelda/Gothic-style real-time combat). One global tile map (`B.g[y][x]`, int per tile, 2 tile layers),
every dynamic thing is a record `int[]` stored in the flat table `B.a[]` (player, NPCs, items, world objects, projectiles, FX).
World coordinates are fixed point: **1 tile = 4096 units**, pixel = `world * B.d >> 12` (B.d/B.e = tile size, **8 px on the world map
(`player[11]==0`), 16 px on normal maps**). Everything is integer logic stepped at **10 Hz**.

## (a) Frame / tick structure

### Main loop (`run()`, line 12660)
```
while (running) {                     // d = time at end of previous iteration
    updateInput();                    // UB(): key->action state + per-state input handling
    if (!paused) updateState();       // C(): per-state logic (state 6 = whole game simulation)
    if (HG.ca) HG.N();                // deferred sound start
    render(screenGraphics);           // W(g): renderState + menu overlay + dialogs
    flushGraphics();
    tickCounter = (tickCounter+1) % 100000;           // p
    sleep(100 - (now - d))  if elapsed < 100          // no catch-up, slows down if > 100ms
}
```
**Logic and rendering are fully coupled: exactly one logic step per rendered frame, target 100 ms (10 fps).** There is no
delta-time anywhere; every "speed" is "units per tick". A slow device simply runs slower.

### What runs per tick in state 6 (`updateState`, line 380; guarded by `synchronized(loaderTask.h)`)
Only executed if `!HG.fA || HG.gA > 17` (i.e. not while a full-screen HG menu 0..17 is open; the in-game inventory style
menus >17 do NOT pause the world):
1. `runScripts()` (TA) – steps up to 4 script contexts (`scriptThreads`), see (e) in section "Scripts".
2. `updateNpcs()` (KA) – only if no message box (`messageBoxOpen`) and no dialogue (`dialogueOpen`).
3. `updatePlayer()` (HA) – movement, attack, target selection, regen; consumes `inputLeft/Right/Up/Down/Action/CycleTarget` then clears them.
4. `updateCamera()` (JA)
5. `updateProjectiles()` (WA), `updateEffects()` (QB), `updateSpellCasts()` (JB) (+ empty stubs LB/MB/NB).
Before this, `updateInput()` (UB) has already run in the same tick and has set the input flags.

### Everything that assumes the 100 ms tick (must be rescaled for a different tick rate or run on a fixed 10 Hz accumulator)
| Place | Tick-dependent detail |
|---|---|
| `updatePlayer` movement | per tick step `player[52]` world units (max `player[16]`=1024 = 0.25 tile/tick = 2.5 tiles/s); diagonal = `isqrt(v*v/2)`; speed ramps `+= player[16]>>3` per tick while a move succeeds, resets to `player[16]>>1` when blocked/idle |
| `updateCamera` | **low-pass filter per tick**: `cam = (cam*100 + target*28) >> 7` (~22 %/tick toward target). Target = player pixel pos - screen/2, shifted 1 tile ahead in facing direction; midpoint between player and locked target when target is on screen. Needs interpolation (or exact per-tick emulation) for high fps |
| `tickCounter` (p) | `p%20==0`: mana regen (3 % of max mana, min 1) every 2 s; `p % npcs.length == i`: NPC i re-targets / re-paths only every N-th tick (staggered AI); `p>>1&3`: animation frame of FX 14 (img 184); `p % ec[1223]`: spell-item sprite frame |
| Animation | `advanceAnim` (C(int[],boolean), line 6952): frame time counter `getAnimTime` increments per tick; frame durations are ticks stored in `animFrameTables[set][variant][anim][frame*5]` |
| Object anim | `updateObjectAnim` (R(int[])): 1 frame per 2 ticks (counter in `[10]>>24`) |
| Footsteps | `footstepCounter` (oB) counts 4 move-ticks per step; sound/animation toggles at 2 and 0 |
| Combat cooldowns | `attackCooldown` (nB--) per tick, formula `5000/(3*weaponSpeed+dex+...)` (`calcAttackDelay`, H(III)) gives ticks; NPC `[21]` attack cooldown, `[26]` aggro counters (counts 20..0 per tick), `[25]` charm/fear timer, `[30]` stuck timer, `[31]` idle-wander timer (20..50 ticks) all decrement per tick |
| Projectiles | `projectiles[i][13]` low = ticks left, linear interpolation `pos = start + delta*ticksLeft/total` per tick |
| Effects/particles | `effects[i][10]` lifetime in ticks (10..128), particle velocities integrated per tick, gravity `-128` per tick (`updateFx0`) |
| Spell casts | `spellCasts[i]` counters (cast time, `[7]` += 10 per tick...) all per tick |
| Script VM | opcode 1 = wait N ticks; many cutscene timings are tick counts in script bytes |
| Wall-clock (the only ones) | splash images: switch every 3000 ms (`splashStartTime`), 1000 ms hold after load (`loadDoneHoldUntil`); `dialogueSkipAllowedAt` = now+500 ms; save slot timestamps `ue/ve` (`System.currentTimeMillis`) |
| Regen/status | `player[17]`(xp) etc. not time based; only mana regen is periodic |

Recommended port approach: keep the logic as is on a fixed 100 ms step, snapshot previous/current `[4],[5]` of every entity
that has flag 8 (player, NPCs, projectiles `kA[4],[5]`, effects) plus camera (`cameraX/Y`) and interpolate at render time. Animation
frame selection can stay tick-quantized (or be time-scaled by `frameDuration*100ms`).

### Threads
* Main/game thread: this `run()`.
* Canvas event thread: `keyPressed/keyReleased` run on it and touch `keyState/actionState` directly (they even call `releaseAllKeys(); updateActionStates();` inside keyPressed).
* Loader thread: `C.run()` -> `setState(3)`, loads the map (`B.A(area,x,y)` / `B.E`) while holding `loaderTask.h`; `updateState`/`renderState` of state 6 synchronize on the same lock, so the game freezes (and state 3 draws the progress bar from `C.c`) until the load ends, then `setState(6)`. `C.run` with `b>0` instead calls `initGame(phase)` (IA) = first boot init (language, data tables, images).
* D (sound thread) is independent.

## (b) State machine and render pipeline

### Game states (`gameState` / `u`)
| u | Meaning | Enter (`onEnterState`) | Per tick (`updateState`) |
|---|---|---|---|
| 1 | Boot: logo image `/s00.png`,`/s01.png` (3 s each) while loader thread runs `initGame` | `loadDataFile()` (reads `/a`) | after both logos + load finished (+1 s): `setState(5)`, `HG.fA=true`, `HG.LA(17)` |
| 2 | Intro slideshow `/s00..sNN.png` (3 s each, key skips) | clears menus, plays `HG.M(0)` | on missing image: fallback image 159 once, then `setState(5)`, `HG.LA(0)` |
| 3 | Map loading (progress bar `C.c`, text `loadingText`) | – | – |
| 4 | Quit | – | `HG.cb.destroyApp(false)` |
| 5 | Main menu / out-of-game | `HG.LA(0)`, ensure image 159 | – (HG menu system runs, `HG.fA`) |
| 6 | In game | – | game simulation above |

Sub-modes inside state 6, evaluated in this priority order by `updateInput()` (line 12191) and drawn by `render()`:
`paused` (key `0`, also set by hideNotify/pauseApp; shows `pauseText`; while paused digits are collected into `cheatCodeBuffer` and compared to hashes in `processCheatCode`) >
`messageBoxOpen` (qC, modal text box with optional quantity chooser) > `dialogueOpen` (kd, NPC/script dialogue + history) >
`lockpickingActive` (qD) > `quickslotAssignMode` (gb) > `quickslotMenuOpen` (fb) > HG in-game menu (`HG.fA`) >
free play. `scriptInputLock` (r, set by script op 76) disables player control during cutscenes. The in-game HG menus: soft key
(action 45 / key code -6) opens menu 18 (or triggers a pending world-map entry), action 50 (-7) opens menu 14; 80/85 = left/right soft
action inside menus; menu ids 19..25 = inventory/container/char pages (see HG notes).

Special game modes:
* **World map** = area id `player[11]==0`. Tile size 8, `renderWorldMap` (E(g)): 2 tile layers baked into the background buffer, only the player marker (img 134) + title banner; `tryWorldMapEncounter()` (GA) rolls encounters when stepping to a new tile (terrain id from layer-1 tile, safe tiles in `noEncounterTiles`), starts a battle-prompt message. Standing on a location marker (script op 75) sets `pendingEnterArea/X/Y`; action key then loads that area.
* Normal area: `renderWorld` (D(g)).

### Render pipeline (all on one Graphics, `render()` = W(g))
`render(g)`: `renderState(g)`; if `HG.fA` then `HG.C(g)` (menu), and if not paused: `drawDialogue` (Q) when dialogueOpen, `drawMessageBox` (N) when messageBoxOpen.
`renderState` (C(g)): paused -> `drawPauseScreen`; else clear black; state 1/3 loading/splash; state 2 splash; state 6:
`player[11]!=0 ? renderWorld : renderWorldMap`, inside `synchronized(loaderTask.h)`.

`renderWorld(g)` (D(g), line 1803), in order:
1. (only if no fullscreen HG menu / not dialogue) visible tile rect from `cameraX/Y`, `screenWidth/Height`, `B.d/B.e`; entity cull rect = visible +-6 tiles in x, rows `top .. bottom+7`.
2. `drawBackgroundBuffer(g)` (F): `bgBuffer` = Image of (screenW/tileW+2) x (screenH/tileH+2) tiles used as a **wrapping scroll buffer**: `updateBackgroundBuffer` (M) redraws only the newly exposed tile columns/rows (`redrawBackgroundRegion` A(IIII)) with **tile layer 0 only** (layer 1 on normal maps is drawn later); the buffer is blitted 4x (wrap-around) with sub-tile pixel offset `cameraX % tileW`. Rebuilt by `createBackgroundBuffer()` (J) at map load: **it is not rebuilt on `sizeChanged`** -> must be re-created when window size changes.
3. Gather entities of all cells in the cull rect from the spatial grid `B.u[y][x]` (chain via `e[1]` low16). Two depth-sorted lists (insertion sort via `insertSorted`, key = `B.A(entity)` = feet y; for objects y+`template[4]`): "overlay" list = world objects (flag 4096) with `e[6]!=0` (tall things), "ground" list = everything else.
4. Shadow pass: every ground-list entity `drawEntity(e, shadowPass=true, g)` (only objects draw something: image `id+177`), player `drawBlobShadow`, every visible NPC `drawBlobShadow` (img 171).
5. Row loop `y` over visible rows: draw ground-list entities with depth `<= (y+1)*4096` (`drawEntity(e,false,g)`), then draw **tile layer 1** cells of that row (tall tiles linked via `B.g` bits 12-14 / 28-30 precomputed by `buildTileOverlapLinks` L(); `drawTileLayerTile(x,y,1,g)`), so tall tiles correctly overlap entities standing behind them.
6. Remaining ground entities, then overlay list (shadow then body).
7. If `!HG.fA`: interaction icon (`drawInteractionIcon`, only when no target), target reticle (`drawTargetReticle`), HUD (`drawHud` S: frame/portrait, HP bar (fixed x=33, 32 px high red) and mana bar, quickslot ring when open, else hover label; `drawTargetBar`; soft key icons at bottom), then dialogue (`drawDialogue`) or lockpicking UI or message box.

`drawEntity` (A(int[],boolean,g), line 1638) picks the sprite per flag: 64/128/256/512/1024/8192 items (icon image `template[1]`, ground/bag variants), 4096 objects (image `sa[t][1]`, frame from `e[10]`), animated models (flag 4) via `drawAnimatedEntity` (B(int[],g), line 6998: composes up to 4 parts per frame from sheets `sheetImages`, rects `spriteRects`, flips via negative tile id), then flag 16/32 -> `drawAnimatedEntity`, 2048 projectile line (`drawProjectile`), 16384 spell projectile, 262144 FX (`drawEffect`). Position on screen: `(e[4]*B.d>>12) - cameraX`, `(e[5]*B.d>>12) - cameraY` (feet), `B.B(e,out)` gives x,y and z (z = `e[6]*4096` for objects with height).

`renderWorldMap` (E(g)): bg buffer (2 layers) only; marker 134; `drawWorldMapBanner`; encounter/message overlays.

Data read by the pipeline: `B.g` (tiles), `B.f` (tileset image ids: low16 layer0, high16 layer1), `B.k` (palette variant for tileset type 5), `B.d/B.e`, `B.b/B.c` (map size in tiles), `B.a` + spatial grid `B.u`, `player[4,5,30,0]`, `cameraX/Y`, image tables `imageTable/imageFrames/images`, model tables `animFrameTables` etc.

### Hard-coded sizes / layout assumptions (relevant for other resolutions and a 3D renderer)
* Tile size is data driven (`B.d/B.e` = 8 or 16); `screenWidth/Height` (f/g) come from `getWidth/getHeight` (full-screen mode) and are used everywhere; the code adapts to any size >= ~128x128. The art (UI images ids 126,138,139,146,147,150,152,155,160,...) is pixel-fixed, positioned by `ec[imageId*11+k]` (image w/h) relative to corners/centre of f,g.
* Fixed: HP bar `fillRect(33, ..., 5, 32)`, mana bar at `(screenW - img138.w - img126.w + 2)`, 32 px bars (`drawHpBar`, `drawManaBar`); quickslot ring layout from `layoutQuickslots`; message box height clamp `g/4 .. 2g/3`, width `f-10`; dialogue rect `yd = f-(2*wd+16)`; target bar `f/8` margins; lockpicking UI centred on `f>>1`.
* Camera clamp: x in `[0, (B.b)*B.d - f]`; y in `[-bannerHeight, (B.c+5)*B.e - g]` (5 extra rows below map for tall sprites; on the world map `[-3*B.e, (B.c+3)*B.e - g]`); maps smaller than the screen are centred.
* Culling margins +-6 tiles / +7 rows assume sprites at most ~7 tiles tall (and tall-tile overlap links max 7 rows).
* Fonts: 3 fixed `Font`s; text placement through the 15 `textAreaRects`.

## (c) Input handling
* `keyPressed(code)` maps codes to 19 internal key indices `0..18`: up(-1)=0, left(-3)=1, right(-4)=2, down(-2)=3, fire(-5)=4, `0`=5, `1`..`9`=6..14, `#`=15, `*`=16, soft -7=17, soft -6=18. `keyRepeated` is empty.
* `keyState[k]`: 20 = pressed this event, 30 = held, 10 = released; `keyReleaseTimer[k]=10` on release. `updateActionStates()` (E) turns that into per-action `actionState` (5 = just pressed, 10 = held) via `ACTION_KEY_MAP` (rows `{actionId, repeatFlag, keyIdx...}`). `isActionPressed(a)` = `state==5 || (state==10 && repeatFlag==15)`. Taps shorter than a tick are not lost.
* **Quirk:** `keyPressed` first calls `releaseAllKeys(); updateActionStates()` which releases every other held key -> only one key can be "held" at a time (hence dedicated diagonal actions on `1,3,7,9`). A port with real multi-key input should feed actions, not keys.
* Action ids (only the ones understood): movement (repeat-capable): 15 up (key up,`2`), 20 down (down,`8`), 25 left (left,`4`), 30 right (right,`6`), 31 up-right (`3`), 32 down-right (`9`), 33 up-left (`1`), 34 down-left (`7`), 35 act/attack (fire,`5`; held = auto attack). Menu: 55 up, 60 down, 61 left, 62 right (also keys 2/8/4/6), 65 confirm (fire,`5`), 80 left soft(-6), 85 right soft (-7) [same keys as 45/50 in game], 90 pause (`0`), 95 `#` (open quickslot menu / back), 100 `*` (cycle target), 101..108,115 digits 1,2,3,4,6,7,8,9,5 as hotkeys, 109..114 inventory shortcuts (`*`,`1`,`3`,`7`,`9`,`#`), 116/117 up/down repeat for quantity chooser, 118 `0`.
* In-game dispatch (state 6, none of the modal modes): 45 -> pending world-map entry (`pendingEnterArea>=0`) or open menu 18 (only if HP>0); 50 -> menu 14; 65 -> interact with `interactEntity` by `interactKind` (pickup, talk, open chest/door/lever, enter loot); 35,15,20,25,30,31..34 set `inputAction/Left/Right/Up/Down` flags (consumed by `updatePlayer`); 95 -> `quickslotMenuOpen`; 100 -> `inputCycleTarget`.
* Port plan: replace `keyPressed/Released` with an action layer that sets `actionState` directly (keep the 19 key slots for compatibility); add true multi-key diagonals (fill `inputLeft/Up...` directly) and analog/WASD.

## (d) Data model reference (needed by renderers / 3D)
* Entity record `int[]` (all in `B.a`; created by `D(int flags)` allocator): `[0]` tile packed (x low16, y high16); `[1]` low16 next entity in same cell, high16 next in sorted render chain; `[2]` low16 index in `B.a`, high16 index in kind array; `[3]` flags: 2 in spatial grid, 4 animated model, 8 free pixel position in `[4],[5]`, 16 player, 32 NPC, 64 weapon, 128 armor, 256 consumable, 512 quest item, 1024 spell item, 2048 projectile, 4096 world object, 8192 jewelry, 16384 spell projectile, 32768 disabled/open, 65536 inactive/dead, 262144 FX, 524288/1048576 hidden-pickup variants, 8388608 player dead. `[4],[5]` world x,y (1/4096 tile) for flag 8; for items `[4]` = template index, `[6]` stack count. `[6],[7],[8],[9],[10]` model state for flag 4 (anim id/time/frame/model set/variant/look/recolor slots). NPC extras: `[11]` template, `[12]` HP (cur low16, max high16), `[13]` behaviour flags, `[14],[15]` weapon instances, `[16]` armor, `[20]` target, `[21]` attack cooldown, `[22]` goal tile, `[23]` home tile, `[24]` path index, `[27]` facing, `[29]` aggro radius.
* Player = `player` `int[55]`: `[4],[5]` pos, `[11]` area id (0 world map, -1 none), `[12]` HP cur|max, `[13]` mana cur|max, `[14]` STR, `[15]` DEX, `[16]` max speed, `[17]` xp, `[18]` level, `[19]` learning points, `[20..24]` weapon skills (1h,2h,bow,xbow,magic), `[25]` lockpicking, `[27..29]` armor values, `[30]` facing (0 N/up, 1 E/right, 2 S/down, 3 W/left), `[31..38]` quickslots (category | index<<16), `[39]` slot-valid mask, `[40]` selected slot, `[41]` armor, `[42]` weapon, `[43]` rings, `[44]` amulet, `[45]` spell, `[46]` gold, `[52]` current speed, `[53]` arrows|bolts.
* Facing is 4-directional everywhere (`directionFromVector`).
* Collision/nav: `navGrid` (half-tile resolution, 3 ints/cell) used by NPC A* (`npcFindPath`, 8-neighbour, cost 5/7, heuristic*10) and `isCellFree`; actual player/NPC movement collision is `B.A(entity,x,y,mask)` in B.
* Scripts: `scripts` (bytecode), `triggers` (type 8 enter rect, 13 leave rect, 18 inside rect, others point triggers), 4 concurrent contexts `scriptThreads`; ~45 opcodes (wait, goto/branches, global vars/flags `scriptVarN`/`globalFlags`, spawn/enable/disable entities, teleport NPC, start dialogue, trainer UI, give/take item, play sound, start map load = opcode 45/41).
* Save/load: `saveGame(slot)` serialises `player, globalFlags, objectStateMasks, collected*Masks, deadNpcMasks, inventory, questLog` via HG RMS helpers; slot 3 and 2 have timestamps. Everything else is reconstructed from map data.

## Hints for other classes
**B (world/map):**
* `B.a[]` is the flat entity table in this order of segments: `[0]` player, then `npcs`, `worldObjects`, `weapons`, `armors`, `consumables`, `questItems`, `jewelry`, `spellItems` (see `findFreeEntitySlot` D(int) lines 1095-1118). `B.g[y][x]`: bits 0-7 layer0 tile, 8-11 layer0 transform (drawRegion transform), 16-23 layer1 tile, 24-27 layer1 transform, bit 15 walkable (`0xFF` = empty), bits 12-14 / 28-30 / 31 overlap links computed in A.L().
* `B.d`/`B.e` = tile pixel width/height (8 on world map, 16 otherwise), `B.b`/`B.c` = map width/height in tiles, `B.f` = packed tileset image ids (layer0 low16, layer1 high16), `B.k` = palette variant (0..4) chosen by area id (4,15 ->1; 6,17 ->2; 7,18 ->3; 12,48 ->4), `B.h` = pending player facing after load, `B.u[y][x]` = first entity of cell (chain `e[1]` low16), `B.s` = next free loot container index (A.lootContainers), `B.nA/oA` in A = prefix/suffix counts (`A.itemAffixes`).
* Used from A: `B.C(e)` insert entity into grid, `B.D(e)` remove, `B.A(e,tx,ty)` re-link at tile (-1,-1 removes), `B.A(e,int[2])` world position, `B.B(e,int[3])` position + height, `B.A(e)` depth key, `B.A(rect,mask)` query entities in rect, `B.A(e,newX,newY,mask)` move with collision (returns -2 if moved), `B.A(x0,y0,x1,y1,mask,out[,bool])` sweep/ray, `B.A(a,b,range)` in-range, `B.F(a,b)` line of sight, `B.G(entity)` item value, `B.E()`/`B.B(int)` per-area object state mask accessors (`A.objectStateMasks`), `B.Q()`/`B.R()`/`B.S()` allocate / prev / next loot container page, `B.M()` computes encounter enemy list (`B.xA` count, `B.yA` types).
**HG:** `HG.fA` is "an HG menu is open" (A branches on it for input, rendering and update gating; menus 0..17 pause the sim, >17 do not). `HG.gA` = current menu id, `HG.hA` selected entry; `HG.M(id)` = playSound; `HG.A(n)` / `HG.A(a,b)` = random; `HG.I(id)` = getText; `HG.LA(id)` = showMenu; `HG.wa/xa/oa` = selected inventory category/index/item record (set by A's input before `HG.DA(menuAction)`); `HG.ya/za` = loot container page / selected index (A.putItemInContainer / takeItemFromContainer). `HG.ia`/`HG.ja` etc. are written by A for item info pages.
**C:** loader thread; `C.c` progress 0..100 read by A's loading screen; field `h` is the lock A synchronizes on; `C.A(A,int)` = boot init (phase b=1 -> `A.IA`), `C.A(A,area,x,y,bool)` = load area; the bool variant reloads the current area at player pos.
**D:** sound worker thread; A only calls `HG.M/…`.

7. `setSlotByte` byte slots 0..7 in `e[9],e[10]`: first `getRecolorSlotCount` slots are palette-swap choices, next `getVariantSlotCount` are variant choices, last `getPartSlotCount` are part choices (equipment looks) – exact roles per model set not confirmed.
